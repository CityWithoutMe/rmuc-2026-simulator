# 局域网联机（1～4 人）

采用一名玩家兼任主机、最多另外三名玩家加入的局域网模式。每人独占一个车位：红方英雄、红方步兵、蓝方英雄、蓝方步兵。复用 SampleScene 内现有四台车辆，不额外生成车辆。

支持主机单人、两人、三人或四人开局；未被选择的车留在场上作为无人操控的车辆，不自动增加 AI。最多四名玩家，开局后仍不允许中途加入。

## 开始游戏

1. 参与本局的 1～4 台电脑使用同一版本客户端，接入同一局域网。
2. 一人进入主菜单的“联网游戏”，点击“创建房间”。默认 TCP 端口为 7777，也可修改。
3. 其他玩家输入房间界面显示的主机局域网 IPv4 地址和相同端口，再点击“通过 IP 加入”。127.0.0.1 仅用于同一电脑多进程测试。
4. 每人选择一台空闲车辆并点击“准备”。已经被其他玩家占用的车位不可重复选择；改变选择会取消准备。
5. 所有已加入玩家准备完成后由主机点击“主机开始本局”，无需满四人。只等待本局实际玩家完成场景初始化后才开始计时和模拟。
6. Esc 解锁鼠标；可以点击右下角“离开房间”。房间内有人断开时，本局终止，重新创建房间再开始。首版没有主机迁移、比赛中途加入或断线重连。

主机需允许应用通过 Windows 防火墙的“专用网络”，并保证 TCP 端口可达。校园网/路由器的客户端隔离可能阻止局域网电脑相互连接。此版本不提供公网匹配、NAT 穿透、账号系统或 Relay 服务。

## 场景约定

现有车辆根名称为 Hero_red、Hero_blue、步兵_red、步兵_blue（英雄英文名称不区分大小写）。它们分别绑定属性管理器中的 red_hero、blue_hero、red_infantry_1、blue_infantry_1。缺失或重名会明确报错并返回房间，不默默复制车辆。

联机运行时只激活这四个属性车位；其他车位不参与统计。退出后重新加载单机场景会恢复原有十车配置。单机“本地跑图”入口保留。

## 架构

- LanTransport：后台线程进行长度分帧的 UTF-8 TCP 收发；不在后台访问 Unity 对象。有消息大小、积压、超时限制。
- LanRoom：主机管理最多四个成员、唯一车位、准备状态、以实际开局人数为准的加载屏障。
- LanSession：房间协议、连接身份、输入和购买请求、心跳、场景切换以及断线清理。操作身份来自连接，不能通过客户端提供的车位冒充其他玩家。
- LanVehicle/LanWorld：每个进程只启用本机玩家的输入和相机。主机运行四车物理与战斗；客户端车辆为运动学展示对象，接收并平滑显示主机位置。
- 客户端约 30Hz 提交输入，主机约 20Hz 广播快照。客户端不自行结算伤害、热量、经验、复活、增益或比赛计时。
- 快照包含四车全部当前数值与状态、属性修饰器、建筑状态、计时和胜负、能量机关灯效/旋转、前哨站旋转位置。弹丸由主机进行碰撞结算，客户端收到发射/消失事件后仅显示视觉弹丸。
- 商店的原有无限金币等训练规则保持原样，联机购买请求改由主机执行。本次没有顺带修正其他比赛规则缺陷。

TCP 是首版局域网实现，不等于完整竞技网络方案。尚无客户端预测、回滚、延迟补偿或公网抗作弊认证；移动显示存在网络往返和快照插值延迟。

## 构建与验证

Unity 菜单“联机 / 构建 Windows 局域网客户端”可生成开发构建，输出为项目 Build/LanBuild/RMNetwork.exe，构建结果记录在 Logs/LanBuild.result.json。构建不保存当前未保存的场景；分发时应包含 exe、同目录的数据文件夹与其他构建文件，而不只复制 exe。构建不放在 Unity 退出时会清空的 Temp 目录。

独立传输/房间测试：

```powershell
dotnet run --project Tests/LanNetworking/LanNetworking.csproj
```

开发构建包含显式命令行的四进程测试入口 LanSmokeTest。普通启动不运行测试。该测试在运行时创建独立测试地面，检查房间按钮、四台车的所属输入、主机物理/客户端展示、单个本地相机、42mm 伤害与升级、客户端兑换立即复活和弹药、主机属性快照。测试不改写场景资产。

```powershell
./Tests/LanNetworking/Run-UnitySmoke.ps1 -Executable ./Build/LanBuild/RMNetwork.exe
```

测试报告和日志保存于 Build/LanSmoke 下的独立时间戳目录。脚本只启动并清理自己的四个测试进程，不关闭 Unity 编辑器。

少人数及积压恢复回归测试示例：

```powershell
./Tests/LanNetworking/Run-UnitySmoke.ps1 -Executable ./Build/LanBuild/RMNetwork.exe -Players 1
./Tests/LanNetworking/Run-UnitySmoke.ps1 -Executable ./Build/LanBuild/RMNetwork.exe -Players 2
./Tests/LanNetworking/Run-UnitySmoke.ps1 -Executable ./Build/LanBuild/RMNetwork.exe -Players 3
./Tests/LanNetworking/Run-UnitySmoke.ps1 -Executable ./Build/LanBuild/RMNetwork.exe -Players 4 -StallClientSeconds 20
./Tests/LanNetworking/Run-UnitySmoke.ps1 -Executable ./Build/LanBuild/RMNetwork.exe -Players 4 -StallHostSeconds 20
```

`-Graphics` 启用真实图形渲染，默认无图形模式。暂停测试只在显式测试启动时运行，普通游戏不会人为暂停。

### 加载/后台掉线修复

联机期间显式开启后台运行，避免切换窗口暂停网络主循环。比赛改为异步加载，并在场景初始化及首帧之后确认准备。加载超时为 180 秒，开局心跳宽限为 60 秒，之后心跳超时为 30 秒。主机请求限速使用网络线程真实收包时间，客户端不再因集中处理主机积压快照而被当成超量请求断开。

当前协议版本为 3，所有电脑都必须更换同一新版完整构建包，不能混用旧客户端。出现退回房间时，Player.log 中的 `[LAN] 返回房间` 会记录具体原因和状态。旧版未记录退回原因，因此这些已确认风险的修复仍需现场复测，不能凭旧日志断言唯一故障原因。

### 场地过程提示与战斗反馈

高地占领、堡垒占领和地形跨越过程提示由主机生成，随各车辆快照同步，结束或取消时同步清空。客户端不自行裁定场地效果。

主机确认后发送命中标记/提示音、伤害与击毁提示、全局击毁播报，以及受击、机器人无敌/防御抵消、基地前哨保护提示。重复保护提示限频。敌我车辆标签只在画面内且视线无遮挡时显示，不透墙。新增敌方前哨、基地血量/护盾及可攻击状态提示。以上不改变伤害与胜负规则。

追加 `-Feedback` 可验证三个进度来源的同步/清空，以及命中、击毁、保护提示与重复保护提示限频，例如：

```powershell
./Tests/LanNetworking/Run-UnitySmoke.ps1 -Executable ./Build/LanBuild/RMNetwork.exe -Players 4 -Feedback -Graphics
```

固定进度和测试提示仅在显式自动测试中注入，普通游戏不运行。

### 本次验证（2026-10-02）

- Unity 6000.3.22f1 Windows 开发构建成功，构建错误数为 0。
- 独立 TCP/房间测试通过 120 项断言（含 1～4 人加载屏障）。
- 同机四个独立 Unity 进程均通过：四人房间按钮与不同车位、每车所属移动输入、每端仅一个本地相机、主机四车物理/客户端零动态车、42mm 命中与经验升级、客户端购买复活及弹药、四端全部属性与主机快照一致。
- 1、2、3 人实际开局通过；四人模式分别模拟主机/客户端主线程暂停 20 秒后恢复，均通过。
- 最终构建还通过四人真实图形模式持续 65 秒测试（超过开局心跳宽限），包含客户端暂停 20 秒、恢复后同步。报告：Build/LanSmoke/20261002-151636-634。
- 以上仍是同机多进程回环网络验证，不等同于现场跨电脑测试，也没有进行人工画面布局验收。现场仍需检查主机 IP、专用网络防火墙、端口可达性及操作手感。
